# 家庭共用待購清單：設計

狀態：設計完成，待使用者審閱。尚未建立雲端專案，也未變更正式網站。

## 1. 使用方式與範圍

沿用現有 GitHub Pages 網址及「待購清單」分頁。同行家人看到同一份購買狀態，輸入旅行專用共用密碼後可以勾選或取消勾選；不需分別註冊帳號。未解鎖訪客只能查看。商品名稱、圖片、分類與既有連結繼續由目前儲存庫維護，不在這次增加雲端商品編輯功能。

密碼已由使用者指定，本文與原始碼都不記錄其值。行前清單及深色模式仍使用各裝置既有設定。

## 2. 儲存與部署方案

採現有 GitHub Pages 前端加獨立的 Sites 雲端 API。Sites 的 Cloudflare Worker 處理驗證與更新，D1 持久儲存購買狀態。Sites 平台文件確認可提供 Worker、D1 與執行期秘密設定；實際後端網址在建立專案後寫入公開設定，只有網址可公開。

選擇理由：不需把目前旅行網站搬家，也不需向使用者索取額外雲端帳號憑證。另一種方案是由使用者另建 Firebase／Supabase 專案，會多出帳號與權限設定步驟；這次不採用。成本尚未取得服務報價，不承諾免費，也不主動啟用付費升級。

新增後端專案與 D1 是這次唯一的雲端基礎設施；不使用 GitHub Issues 或公開 JSON 檔記錄家人的勾選。

## 3. 驗證與 API

公開 `GET /api/shopping` 只傳回允許清單中的商品 ID、已購買布林值及更新版本，不含家人姓名或其他個人資料。

`POST /api/unlock` 在伺服器驗證密碼，成功後發給高熵隨機憑證，效期30天。憑證僅存目前瀏覽器；退出共用模式時撤銷該裝置憑證。伺服器只保存憑證雜湊。密碼以加鹽衍生值置於執行期秘密設定，明碼不存 Git、不進瀏覽器程式、不進記錄或版本說明。

`PUT /api/shopping/:itemId` 必須帶有效憑證，只接受已知商品 ID 及布林購買狀態。所有輸入在伺服器驗證。`POST /api/logout` 撤銷當前裝置憑證，不影響其他家人。前端跨來源請求使用 Bearer 憑證，不依賴跨站 Cookie；允許來源限制為目前 GitHub Pages 的來源。

對短密碼加入伺服器端錯誤次數限制與暫時鎖定；驗證與更新不記錄密碼、憑證或明碼 IP。必要的節流識別使用雜湊並定期到期。D1 以正式 migration 建表，不在每次請求時建表。

## 4. 同步與例外處理

分頁可見且連線正常時每5秒讀取一次，也在切回分頁及恢復連線時立即讀取。不同裝置更新同一品項，以伺服器最後接受的單品更新為準；各品項分開寫入，避免整份清單覆蓋。

勾選送出時暫停該項操作；伺服器成功才顯示已同步。失敗就恢復最後確認狀態並顯示重試提示，不把失敗更新假裝保存成功。離線可查看最後一次成功同步的快取，暫停修改；不背景重送舊操作覆蓋家人較新的選擇。

切換至共用狀態時不自動上傳舊的裝置本機勾選，也不刪除既有本機記錄。無法讀取雲端時明確顯示「暫時無法同步」，不切換成可修改的本機清單。

畫面只新增「家庭共用」狀態、密碼解鎖欄、退出按鈕與簡短同步狀態。密碼欄採 password 輸入型態；手機、桌機及深色模式沿用現有樣式。

## 5. 驗收與發布

以兩個隔離瀏覽器工作階段驗證：解鎖後 A 勾選、B 在5秒輪詢週期內收到更新；B 取消後 A 同步；重新整理狀態保留。驗證錯誤密碼、到期／撤銷憑證、未解鎖寫入、節流、未知商品、異常輸入與離線失敗處理。既有行前清單不受共用購物狀態影響。

檢查公開原始碼與部署檔沒有密碼或憑證，並測試 iPhone 15、iPhone 16 Pro、桌機及深淺色版面。後端完成部署並通過真實雙裝置工作階段測試後，才發布 GitHub Pages 前端、更新 vx.y 與版本紀錄。若後端尚未就緒，不將共用功能標示成已上線。

本設計通過後，依 brainstorming 工作流程撰寫實作計畫，再進入實作。
